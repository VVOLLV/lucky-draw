# 幸运抽奖 · Lucky Draw

单文件、零依赖的现场抽奖网页：分组揭晓 + 3D 翻牌动画 + 深浅双主题。

## 为什么做这个

在 Trae on Campus 活动现场，我给自己出了个题：用 30 分钟、全程靠 TRAE，做一个**真的能抽**的抽奖网站——不是原型截图，而是名单真实、公平不重复、投屏就能用的东西。可靠是第一目标，好看有趣是第二目标。

## 特性

- **分组抽奖**：默认按 5 → 3 → 1 → 1 依次揭晓，抽满自动结束
- **3D 翻牌**：中奖格从虚线空位翻出中奖名字，翻完掠过一道高光
- **深浅双主题**：右上角一键切换；浅色对齐 TraeWork Light 规范（白底 + 靛紫品牌色），偏好自动持久化，刷新不闪烁
- **参与名单侧栏**：可开关、可全屏展开，实时显示人数统计，已中奖者高亮
- **不重复中奖**：名单去重，每人最多中一次
- **单文件零依赖**：不联网也能跑，双击即用

## 使用

直接双击打开 `index.html`。或在目录下起一个本地服务：

```bash
python3 -m http.server 8123
```

然后访问 <http://localhost:8123>。

## 操作

点「开始抽奖」→ 名字滚动 → 再点「停！」→ 本组中奖者一起亮出。抽完一组按钮变为「抽下一组」，「重置」清空重来。右上角 ☀/☾ 按钮切换深色/浅色主题。

## 自定义

改 `index.html` 底部的几个常量即可：

| 位置 | 说明 |
| --- | --- |
| `PARTICIPANTS` | 候选人名单，一行一个名字 |
| `GROUPS` | 分组与人数，`{ label, count }`，数组顺序即抽取顺序 |
| `ROLL_INTERVAL` | 滚动速度（毫秒，越小越快） |
| `:root` | 设计 token：配色、圆角、字号，改一处全局生效 |

总人数由 `GROUPS` 自动汇总，无需手改。

## 关键取舍

这些是过程中真实做过的决策，记录下放弃了什么、为什么：

| 决策 | 放弃了什么 | 为什么 |
| --- | --- | --- |
| 单文件、零依赖 | 工程化拆分、框架、CDN | 30 分钟时限；现场网络不可靠（后来推送 GitHub 果然超时），双击就能跑的演示零风险 |
| 系统字体栈 | 更讲究的外部字体 | 断网时 web font 加载失败反而掉档，不如直接用稳的 |
| 名单去重（146 行 → 139 人） | 同名者各自参赛 | 同一名字中两次比少一人更伤现场信任；确有同名再加后缀区分即可 |
| 分组一起亮（5 → 3 → 1 → 1） | 逐个揭晓的悬念 | 现场节奏更快，一组一次高潮，翻牌同帧进行保住"一起亮"的仪式感 |
| 中奖态极简风（白字 + 品牌色描边） | 金色渐变 | 金渐变显廉价、与 TRAE 气质不符；白字在深底上更干净 |
| 浅色模式换靛紫品牌色 | 跨主题统一用绿 | 遵循 TraeWork Light 规范；且绿字在白底上对比度不足 |
| 纯静态、无后端 | 中奖记录持久化 | 一次性演示场景，为它引入服务端不值得，刷新即重置反而方便 |
| data-theme + head 内联初始化 | 一点实现复杂度 | 换主题时闪一下深底，演示观感直接掉档；localStorage 记住偏好 |
